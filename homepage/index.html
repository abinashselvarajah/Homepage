Synthetic vs. Real

Can virtual images replace real ones when training industrial recognition systems? My project investigates how suitable synthetic data is.

I started from a real image dataset of 3D-modelled Makeblock parts and recreated it in Unity. With the Perception tool, I generated synthetic images using domain randomizers for colour, rotation, texture, background and sun angle, which adds the variety a purely virtual dataset lacks.

On this data I trained a CNN for image classification in Keras and an SSD MobileNet V2 model for object detection with TensorFlow. I first compared the randomized parameters one by one, then trained networks on different shares of real and synthetic images and evaluated them with accuracy and detection metrics.

The result: synthetic data is a good way to extend a real dataset, but only if the randomization is chosen with care.

Robotics

Autonomous Vehicles and Artificial Intelligence 2023

Can a small robot drive a racetrack on its own, using only a camera and LiDAR? In the course Autonomous Vehicles and AI, our group built the full software stack for a TurtleBot3.

We derived requirements with the WISE Drive framework and implemented the system as ROS 2 nodes. A camera node feeds a YOLOv5 model, trained with Roboflow on Google Colab, that detects the coloured cones. LiDAR data is fused with the detections to place each cone in space, Cartographer SLAM corrects the drifting odometry, and an occupancy map collects the cone positions. A movement controller then steers towards the next target point between the nearest blue and yellow cone.

The TurtleBot drives simple and round racetracks autonomously. The main limits were odometry drift and the processing delay of the on-board hardware.

Autonomous Vehicles and Artificial Intelligence 2025

Same challenge, faster hardware: can the approach also drive an F1TENTH racecar through a cone track? In the follow-up course, we ported our stack to the racecar.

A RealSense camera feeds a YOLOv11 Nano model for cone detection. We trained it on real images and compared different shares of synthetic images, from 0 to 100 %, as well as many negative samples. The detections are fused with LiDAR data, clustered with DBSCAN and collected in an occupancy map. The controller drives to the midpoint between the nearest blue and yellow cone ahead; if only one colour is visible, it predicts the missing cone or explores until both are in view.

In sufficient conditions, the racecar navigates the track using only camera and LiDAR. Most of the driving code had to be rewritten, because the racecar steers fundamentally differently from the TurtleBot.

Human-Centered Robotics

How can a robot help a worker with cerebral palsy to press small rubber and metal parts together in a sheltered workshop?

Based on a visit to the workshop, we defined a persona and requirements and developed the system in Scrum sprints. The dual-arm ABB YuMi is controlled from Python, with motion targets taught by hand and stored in a JSON file. OpenCV locates each part and its orientation from a 4K webcam image using edge detection and principal component analysis, and a 3D-printed holder keeps the metal part stable. The worker controls the robot by voice: the hot word “Hey YuMi” is detected with Picovoice Porcupine, speech is processed with Google Speech-to-Text and the OpenAI API provides small talk, while an emergency stop secures every movement.

The system meets all requirements we set. What remains is analysing occasional robot errors, such as a sudden loss of calibration.

Natural Language Processing

Membership Inference Attacks

Can we tell whether a text was part of a language model’s training data? This matters for copyright violations and private data leakage.

Existing attacks are often evaluated on data with a clear distribution shift, so I aggregate many attacks to find the most reliable signals. I extended an existing multi-scale framework from 10 to 644 features by adding reference-model-based attacks, and replaced its linear aggregator with Logistic Regression, an MLP, XGBoost, Random Forest and an SVC. The attack is evaluated on Pythia-2.8B and Pythia-6.9B over eight subsets of The Pile, and on models protected with the DuoLearn defense.

LLMs for Repurposing

Can large language models find ways to repurpose used products in a circular economy? This study evaluates GPT-5, Claude Sonnet 4.5 and Gemini 2.5 Pro on documented cases from the literature, as a co-author of the DESIGN 2026 paper.

Based on a systematic literature review, a validated dataset of 72 repurposing cases was built. Structured zero-shot prompts ask each model for ten repurposing scenarios and the properties needed to realise them. I was involved in setting up the experiments with the different models, which were run through their official APIs with ten runs per query, 3,120 runs in total. Outputs were compared to the dataset semantically with LLMs, followed by manual verification.

Blue Team vs. Red Team

How well does differential privacy protect a text classifier against membership inference? In the course Privacy-Preserving NLP, we played both sides.

As the defender, we trained a DistilBERT sentiment classifier on IMDB movie reviews with DP-SGD from Opacus at different privacy budgets ε. As the attacker, we used the robust membership inference attack (RMIA) and the Likelihood Ratio Attack (LiRA) on balanced sets of member and non-member samples, and compared attack AUC with accuracy and F1.

Reinforcement Learning

Exploration vs. Exploitation

How much should an agent explore, and how much should it exploit what it already knows? We compared four exploration strategies on the task of solving mazes.

We built a standardized framework on Stable Baselines 3 and trained a DQN agent with constant ε-greedy, annealed ε-greedy, Count Based exploration and Upper Confidence Bound (UCB). The environment is our own Gymnasium maze that generates random labyrinths from a seed: the agent starts in one corner and must reach the goal in the opposite corner. The goal gives a reward of 100, every step costs 1. We trained on 10×10 and 20×20 mazes with several seeds, once with dense rewards along the shortest path and once with sparse rewards, and tracked all runs in Weights & Biases.

Graph Database

MaLeNa

Which phones share the same display, battery or chipset, and so which parts could get a second life? In the MaLeNa project, which looks at re-using parts of end-of-life products, I built the data basis for this question: a graph database of phone specifications.

A scraper reads the datasheet pages of phonedb.net, following its robots.txt and waiting between requests, and splits each page into sections such as Display, Power Supply or Chipset. These become a Neo4j graph of products, components and properties, where values and units are shared nodes. A final merge step fingerprints every component with APOC and collapses identical ones into a single node that several phones point to.

The result is a graph in which shared parts are one hop apart, so a single Cypher query answers which phones have the same display or battery.
